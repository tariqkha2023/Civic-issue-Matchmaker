1 / 20 · OpenStreetMap iD

Let custom background maps specify the size of their image tiles.

Original title: Add a parameter to support custom {tileSize} of WMTS backgrounds

What this project does

A browser editor for contributing to OpenStreetMap. Project source

Background

OpenStreetMap is a shared map that contributors can edit. iD is the browser-based tool they use to add or correct mapped objects, such as roads and buildings. Background imagery gives them a visual reference while editing. Online imagery often arrives as many small square pictures called tiles, which the editor assembles into a larger view. WMTS, short for Web Map Tile Service, is a standard for requesting those pictures. Tile size is the width and height of each picture in pixels. The issue asks for a setting that lets an imagery source specify that size. ELI, the Editor Layer Index, is the catalogue of imagery sources mentioned by the author.

Motivation

The author wants iD to support more WMTS imagery sources. They report a service that would not open in iD 2.20.1.

Work described

The request is for a configurable tile-size parameter. The saved issue describes a 256-pixel default and mentions 512 × 512 imagery; it does not prescribe a complete implementation.

What still needs clarification

The historical code links could not be retrieved in this review. The reported default is attributed to the issue author, not verified against today’s code. The parameter format, accepted sizes and current bug status still need checking.

4 / 20 · Open Food Facts

Compare the ingredient makeup of groups of food products.

Original title: Project Recipes: analyze the distribution of ingredients in a set of products (e.g. vegetables and meat in pizzas)

What this project does

An open database of food products, ingredients and nutrition information. Project source

Background

Open Food Facts stores ingredient lists and nutrition information from food packaging. Nutrition information describes properties such as sugar or fat content; an ingredient list describes what a food is made from. This proposal concerns comparing ingredients across a group of products, such as different pizzas. A parent ingredient is a broader grouping: apple would count toward fruit. The proposed software would estimate how much of each grouping a product contains, then calculate averages and show how products differ. Those estimates could support comparisons and research, but they would not be measured or manufacturer-confirmed recipes unless the source data established that.

Motivation

Researchers, consumers and producers could compare products, including estimating typical recipes for environmental-impact research.

Work described

The author proposes estimating ingredient percentages, grouping ingredients into broader categories such as fruit, calculating statistics, then exposing results through scripts and eventually a web interface.

What still needs clarification

The initial deliverable, accuracy expectations and handling of missing ingredient quantities need definition. The proposal names Ingredients.pm, but its implementation was not inspected.

Original posting and sources

Task claims above are paraphrases of this saved posting unless marked as interpretation. Background comes from the project documentation and sources below. Live issue status and comments were not comprehensively rechecked.

### What

- We can easily compare nutrition facts for a set of products (with graphs, Nutri-Score etc.) but there is currently no way to compare their ingredients. For instance comparing the % of meat, milk, fruits, vegetables, added sugar etc. for a specific category of products.

- The Project Recipes is to add features to do that, for research purposes (e.g. the makers of Agribalyse are very interested to have average recipes for categories of products, so that they can use those recipes to estimate the environmental impact of an average product), but also so that consumers and producers can quickly see how a product compares to others.

- The basic features would be to select parent ingredients of interest (e.g. meat, fish, fruits etc.) and a set of products, and get information on the distribution of those parent ingredients for the set of products.

- The information could be basic stats (mean, variance etc.) and distribution graphs.

- We could also allow to see which products have the less or the more % of specific parent ingredients, and to compare a specific product with the average (like we have today for nutrition facts for products of the same category).


### Proposed solution

- The ingredients list is first analyzed with the Ingredients.pm module to identify each ingredient and estimate the percentage of each ingredient.

- Then each ingredient is matched against the specified list of parents ingredients. (e.g. if we want the distribution of water, sugar and fruits, "apple" will be mapped to fruits.)

- We can first implement the backend computations, make them available through scripts etc. and then build a web interface to integrate those functions with facets, graphs etc.
